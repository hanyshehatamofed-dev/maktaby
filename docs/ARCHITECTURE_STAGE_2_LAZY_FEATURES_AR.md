# مكتبي PRO 10.9.1 — إعادة الهيكلة المعمارية / المرحلة الثانية

## نطاق التنفيذ
تم عزل وحدتين وظيفيتين من ملف التشغيل الرئيسي وتحميلهما عند أول طلب من المستخدم، بدل تحميلهما مع النواة الأساسية.

### 1. تقارير وإنجازات الموظفين
- نقل واجهة الإنجازات الشهرية وطلبات اعتماد الإنجازات إلى `src/js/maktaby-achievements.js`.
- الحفاظ على ربط الاعتماد بجدول `approval_requests` وبيانات `db.achievements` الموجودة.
- الحفاظ على صلاحيات المدير/مديرة المكتب واعتماد الإنجاز قبل احتسابه.
- تحميل الوحدة عند فتح «إنجازات الموظفين» فقط.

### 2. CRM العملاء المحتملون
- نقل وحدة CRM إلى `src/js/maktaby-crm.js`.
- الحفاظ على عمليات القراءة والحفظ والمتابعة والأرشفة والاستعادة والتحويل إلى موكل، دون تغيير مخطط قاعدة البيانات.
- الحفاظ على شرط الصلاحية `canManageOffice()` والتحقق من التكرار ومنع إنشاء ملف موكل مكرر.
- إيقاف تحميل سجل CRM الكامل عند بدء التطبيق؛ لا تُحمّل الوحدة ولا بيانات العملاء المحتملين إلا عند فتح القسم.

### 3. التحميل والكاش
- أضيفت نقطة تحميل مؤجل للوحدتين في مشغل التطبيق.
- الوحدتان غير مدرجتين في قائمة ملفات Service Worker الأساسية؛ لذلك لا تُحمّلان ضمن كاش بدء التشغيل.
- بعد أول تحميل، يعاد استخدام الوعد المحفوظ للوحدة لمنع إدراج `<script>` أكثر من مرة.
- بقيت الوحدات Classic Scripts عمدًا في هذه المرحلة حتى تظل متوافقة مع الاعتماديات العامة والـ lexical bindings المتراكمة في `renderer.js`. هذا تحميل كسول فعلي، لكنه ليس بعد تحويلًا كاملًا إلى ES modules مستقلة.

## قياس الحجم
- قبل الفصل: `renderer.js` = 558,807 بايت.
- بعد الفصل: `renderer.js` = 518,128 بايت.
- مقدار التخفيض: 40,679 بايت (حوالي 7.3%).
- الوحدات المنقولة: CRM = 29,395 بايت، والإنجازات والتقارير = 11,605 بايت.
- لم يتحقق بعد الهدف النهائي لنواة 80–120 كيلوبايت؛ هذه خطوة أولى ضمن تفكيك متتابع، ولا ينبغي اعتبارها نهاية تقليص الملف.

## الاختبارات
- `npm run qa`: نجحت جميع مجموعات QA الثابتة الموجودة، بما فيها اختبارات المهام والجلسات، أدوات القضايا، المزامنة، الاسترداد، النظرة الأسبوعية، بنية البناء، واختبار الفصل الجديد.
- `node --check`: نجح فحص syntax لملف `renderer.js` والوحدتين والـ inline module scripts.
- اختبار الفصل الجديد: 16/16 تحققًا ثابتًا.
- هذه الاختبارات لا تتصل بقاعدة Supabase الحية ولا تثبت سلوك واجهة المستخدم في متصفح فعلي.

## ما لم يكتمل بعد
- لم ينفذ `vite build` لأن اعتماد Vite غير موجود في بيئة التنفيذ (`vite: not found`) ولم يتوفر تنزيل npm هنا. لذلك هذه حزمة مصدر لا حزمة `dist` جاهزة للنشر.
- لم يتم اختبار تسجيل الدخول الفعلي أو RLS أو عمليات CRM على قاعدة حية.
- لم يتم الوصول بعد إلى نواة 80–120 كيلوبايت. المرحلة التالية تفصل وحدات التقارير المتبقية ثم أجزاء العملاء والقضايا تدريجيًا مع اختبارات ربط وحفظ.

## الإصدار والنطاق
الإصدار باقٍ `10.9.1`؛ التغييرات صيانة معمارية داخلية. النطاق ويب فقط، دون Windows أو تغييرات SQL أو حذف بيانات.
