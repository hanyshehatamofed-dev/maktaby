# تقرير مراجعة MAKTABY PRO 10.9.1 — دورة المهام والجلسات

## نطاق التعديل
- إصلاح مسار إنهاء المهام من نموذج التعديل والزر المباشر، مع توحيد الحالات `تم التنفيذ` و`منتهي` و`منفذ` والقيم الإنجليزية المكافئة.
- عند اختيار الموظف «تم التنفيذ» من نموذج المهمة، يُرسل طلب إنهاء للإدارة بدل إعادة الحالة القديمة بصمت؛ لا تُؤرشف المهمة إلا بعد الاعتماد.
- توحيد الأرشفة في معالج واحد، ومنع التكرار عند إعادة المحاولة، ومعالجة إعادة اعتماد طلب سبق حفظ أرشفته.
- إدخال `taskArchive` و`achievements` ضمن بيانات الحالة التشغيلية المشتركة والموظفين، واستعادتهما عند تحميل البيانات.
- تقليل حمل حفظ المهام والجلسات: استخدام نفس RPC الذري مع إرسال الحالة التشغيلية فقط، دون قراءة أو إعادة كتابة السجل المالي عند كل تعديل مهمة أو جلسة.
- عند تجاوز تاريخ الجلسة دون قرار، تُنشأ مهمة متابعة ثابتة مرتبطة بالقضية، وتضم اسم الموكل/الموكلين، رقم الدعوى، موضوعها، المحكمة، الدائرة، مكان الانعقاد، رقم الرول، نوع القضية وتاريخ الجلسة.
- منع إنشاء مهمة مكررة للجلسة نفسها، وفحص الجلسات دوريًا أثناء بقاء البرنامج مفتوحًا.
- فصل الجلسات المنتهية دون قرار في أعلى صفحة «القضايا والجلسات» تحت «جلسات مطلوب قرارها»، مع بقاء الجلسات الأخرى أسفلها في الصفحة نفسها.
- عند إدخال القرار وتاريخ الجلسة التالية، يُحفظ القرار وبيانات الجلسة القديمة في سجل التاريخ، وتُؤرشف مهمة تحصيل القرار، وتعود القضية إلى ترتيب الجلسات حسب موعدها الجديد.
- لا يمكن ترحيل جلسة منتهية إلى موعد جديد دون إدخال قرارها؛ وللحكم النهائي يُستخدم مسار أرشفة القضية المعتاد.

## الحفاظ على البيانات والصلاحيات
- رقم الإصدار بقي `10.9.1`؛ تم تحديث معرّف البناء والكاش فقط.
- لا توجد تغييرات SQL أو جداول أو سياسات RLS.
- لم يتم تعديل الحسابات أو الحركات المالية أو قواعد الأتعاب.
- لم يتم نشر الحزمة على Cloudflare ولم يتم إجراء اختبار حي على Supabase.
- تعذر المزامنة السحابية العام ما زال يحتاج متابعة مستقلة؛ تقليل طلبات قراءة السجل المالي لا يُعد إثباتًا لإصلاح مهلة قاعدة البيانات.

## الاختبارات المحلية
- `node --check` لملف التشغيل الرئيسي: ناجح.
- اختبارات منطق المهام والجلسات: **23/23 ناجحة**.
- الاختبارات شملت: إنشاء مهمة واحدة لكل جلسة متأخرة، اكتمال بيانات المهمة، منع التكرار، أرشفة المهمة، إعادة المحاولة، انتقال الجلسة من قائمة مطلوب قرارها بعد تسجيل القرار والموعد الجديد، ومزامنة الأرشيف في الحالة التشغيلية.
- لم تُختبر واجهة المستخدم على حساب المكتب الفعلي أو أجهزة متعددة، ولم يُختبر Realtime أو نشر Cloudflare.

## قرار المراجعة
مرشح ويب للصيانة والاختبار الداخلي فقط. لا يُعتبر منشورًا أو مختبرًا على الإنتاج.
