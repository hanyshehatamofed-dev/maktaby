# تقرير المرحلة الثالثة — مكتبي PRO 10.9.1

## المنفذ فعليًا
- إضافة `maktaby-store.js` كطبقة أحداث Pub/Sub خفيفة (`on`, `once`, `emit`, `listenerCount`) دون نقل مصدر البيانات أو تغيير آلية الحفظ.
- تحميل طبقة الأحداث قبل ملف التشغيل الرئيسي.
- بث حدث `view:rendered` بعد إعادة العرض وحدث `appeal:calculated` بعد حفظ حساب طعن. هذه بداية تكامل قابلة للتوسع وليست ترحيلًا كاملًا لكل أحداث النطاقات.
- تحويل حاسبة الطعون والتنبيهات في شاشة القضايا إلى لوحة تُفتح من زر عائم «أدوات الجلسات»، وتظل مغلقة افتراضيًا، مع إخفاء الزر عند مغادرة شاشة القضايا.
- تحديث Service Worker لتخزين ملف طبقة الأحداث محليًا مع تغيير اسم cache لمنع تقديم ملفات قديمة.
- إضافة إعداد Vite فعلي يخرج إلى `dist` ويستبعد ملفات QA من الإنتاج، ويعطل sourcemaps في build الإنتاج.

## ما لم يتم نقله عمدًا
لم يتم نقل وظائف القضايا والجلسات والموكلين والطباعة والإعلانات دفعة واحدة إلى خمسة ملفات مستقلة؛ لأن الملف الحالي يعتمد على lexical globals ودوال متداخلة وامتدادات متراكمة. النقل الميكانيكي الآن قد يسبب أخطاء حفظ أو صلاحيات أو مزامنة. كما أن إنشاء ملفات بأسماء modules دون نقل حقيقي سيعطي انطباعًا مضللًا.

## حدود التحقق
لم يتم تشغيل `npm install` أو `vite build` لعدم توفر تحقق من تنزيل الاعتماديات في هذه البيئة. يلزم تشغيل `npm ci` ثم `npm run build` في بيئة المشروع. لم يتم اختبار Cloudflare أو Supabase الحي، ولم يتم تعديل SQL أو RLS أو localStorage/IndexedDB.
